# 앱박스 푸시 연동 점검

푸시가 오지 않는다는 문의를 앱박스 MCP 도구로 점검하고, 결과를 한국어로 정리해 사용자에게 알려 준다.
이 스킬은 **조회만** 한다. 설정 변경·발송·키 발급은 하지 않고, 필요하면 앱박스 콘솔에서 할 일을 안내한다.

사용자가 넘긴 인자: `$ARGUMENTS` (비어 있을 수 있음)

## 절차

### 1. 대상 앱 확정 — `appbox_list_apps`

1. `appbox_list_apps` 를 호출한다. `nextCursor` 가 `null` 이 아니고 대상 앱을 아직 못 찾았으면 `cursor` 로 다음 페이지를 이어서 조회한다.
2. 인자나 대화에서 앱 코드(`app`) 또는 앱 이름이 주어졌으면 목록에서 일치하는 앱을 고른다.
   - 앱 코드는 대소문자를 그대로 쓴다. 이름이 여러 앱과 겹치면 후보를 보여 주고 사용자에게 고르게 한다.
3. 앱이 하나뿐이면 그 앱으로 진행한다. 여러 개인데 단서가 없으면 목록(이름·앱 코드·플랜)을 보여 주고 어떤 앱인지 묻는다.
4. 목록이 비어 있으면 "이 연결로 볼 수 있는 앱이 없습니다"라고 알리고, 콘솔 계정 설정 › MCP 연결의 「허용 앱 변경」에서 앱을 체크하거나 로그인한 계정이 맞는지 확인하도록 안내한 뒤 멈춘다(결과의 `notice` 가 있으면 그대로 전한다).
5. 고른 앱이 `isDemo: true` 면 데모 앱이라 실제 고객 기기 상황과 다를 수 있다고 덧붙인다.

### 2. 연동 점검 — `appbox_check_app_setup`

`appbox_check_app_setup` 에 `{ "app": "<앱 코드>" }` 를 넘긴다. 응답의 `checks` 배열을 항목별로 해석한다.

| 항목 | 상태 | 의미와 안내 |
|---|---|---|
| `FCM` | `MISSING` | FCM 이 등록되지 않았다. 푸시가 갈 수 없는 상태다. 앱박스 콘솔의 빌드 > FCM 설정을 마치도록 안내한다 |
| `DEVICES` | `MISSING` | 수신 허용 기기가 0대다. 앱에 SDK 가 연동돼 있는지, 앱을 설치·실행했는지, 알림 권한을 허용했는지 확인하도록 안내한다 |
| `DEVICES` | `WARN` | 마지막 기기 활동이 30일 넘게 없다. 최근 빌드가 배포됐는지, 새 빌드에서 SDK 초기화가 빠지지 않았는지 확인하도록 안내한다 |
| `API_KEY` | `MISSING` | 서버 API 키가 발급되지 않았다. 고객 서버에서 API 로 발송하는 경우에만 필요하다. 콘솔에서 직접 발송한다면 무시해도 된다고 알린다 |
| 모든 항목 | `OK` | 설정은 갖춰져 있다. 3단계로 넘어간다 |

- 각 항목의 `note` 는 서버가 준 설명이다. 표의 안내와 함께 그대로 전달한다.
- `devices.android`·`devices.ios`·`devices.testers` 는 **수신 허용 기기 수**다(콘솔 대시보드와 같은 기준). 특정 OS 만 0이면 그 OS 쪽 연동(예: iOS APNs 설정, 알림 권한)을 먼저 의심하도록 안내한다.
- `lastDeviceActivityAt` 이 `null` 이면 "기기 활동 기록 없음"으로 표시한다.

### 3. (필요할 때만) 빌드 상태 — `appbox_get_build_status`

설정이 모두 `OK` 인데도 푸시가 안 온다거나, `DEVICES` 가 `MISSING`·`WARN` 이고 사용자가 최근 빌드를 언급하면 `appbox_get_build_status` 에 `{ "app": "<앱 코드>" }` 를 넘겨 최근 빌드를 확인한다.

- `recent` 의 최신 항목이 `FAILED`·`TF_FAILED` 면 `errorCode` 와 함께 "최근 빌드가 실패해 새 SDK 설정이 반영되지 않았을 수 있다"고 알린다.
- `active` 가 있으면 빌드가 진행 중이라고 알린다.
- 데모 앱은 빌드 이력이 비어 있는 것이 정상이다.

### 3-1. (특정 사용자·기기에만 안 올 때) 기기 상태 — `appbox_find_device`

"이 회원에게만 안 와요"처럼 대상이 특정되면 `appbox_find_device` 에 `{ "app": "<앱 코드>", "memberId": "<고객사 회원 ID>" }` 또는 `{ "app": …, "deviceId": "<기기 식별자>" }` 를 넘긴다(둘 중 하나만). 서버가 이 도구를 제공하지 않으면 건너뛴다.

- 결과가 비어 있으면 그 회원 ID 로 등록된 기기가 없다 — 앱이 SDK 로 memberId 를 보내는지, 그 기기에서 앱을 실행했는지 확인하도록 안내한다.
- `hasPushToken: false` 면 토큰이 등록되지 않았다(알림 권한 거부, iOS 는 APNs 설정). `receiveEnabled: false` 면 수신 거부 상태라 일반 발송에서 빠진다.
- `lastActiveAt` 이 오래됐으면 앱을 지웠거나 오래 쓰지 않은 기기일 수 있다.
- 푸시 토큰 값은 돌려주지 않는다. 사용자에게 토큰을 붙여 달라고 하지 않는다.

### 4. 결과 정리 (한국어)

아래 형식으로 짧게 정리한다. 도구가 돌려준 값만 쓰고, 없는 값을 추측해 채우지 않는다.

```
## <앱 이름> (<앱 코드>) 푸시 연동 점검

- FCM: 등록됨 / 미등록
- 수신 허용 기기: Android N대 · iOS N대 · 테스터 N대
- 마지막 기기 활동: YYYY-MM-DD HH:mm (KST) / 기록 없음
- 서버 API 키: 발급됨 / 미발급

### 판단
- (가장 가능성 높은 원인 1~2개)

### 다음 할 일
1. (사용자가 콘솔·앱에서 할 일, 순서대로)
```

- 시각은 응답 값(+09:00)을 그대로 KST 로 읽어 표시한다.
- 문제가 없으면 "앱박스 쪽 설정은 정상입니다"라고 쓰고, 기기 쪽 확인 항목(알림 권한, 방해 금지 모드, 앱 강제 종료 여부)을 안내한다.

## 오류 처리

도구 오류는 `isError: true` 와 함께 `content[0].text` 에 `{"error":{"code","message","hint",…}}` JSON 으로 온다. `message`·`hint` 는 서버가 쓴 한국어 문구이므로 그대로 전달하고, 아래 안내를 덧붙인다.

| 코드 | 안내 |
|---|---|
| `INVALID_INPUT` | 입력이 잘못됐다(`fields` 참고). 앱 코드는 콘솔 URL 에 보이는 영숫자·하이픈 10자 이하 값이다. 1단계로 돌아가 목록에서 코드를 다시 확인한다 |
| `APP_NOT_FOUND` | 앱이 없거나 이 계정의 앱이 아니다. 목록에서 앱 코드를 다시 고른다 |
| `APP_NOT_ALLOWED` | 내 앱이지만 이 연결에 허용하지 않은 앱이다(연결한 뒤 만든 앱도 여기에 해당). AI 앱에서 앱박스 연결을 다시 하고 허용 화면에서 이 앱을 체크하도록 안내한다 |
| `RATE_LIMITED` | 호출 상한 초과. `retryAfterSec` 초 뒤에 다시 시도하자고 알린다. 자동으로 반복 호출하지 않는다 |
| `BUSY` | 서버가 바쁘다. `retryAfterSec` 초 뒤 한 번만 다시 시도한다 |
| `TIMEOUT` | 조회 시간 초과. 잠시 뒤 한 번만 다시 시도하고, 반복되면 앱박스 고객지원에 문의하도록 안내한다 |
| `TOOL_DISABLED` | 앱박스가 이 도구를 일시적으로 막아 두었다. 콘솔에서 직접 확인하도록 안내한다 |
| `INTERNAL` | 서버 오류. `traceId` 를 함께 전달하고 고객지원 문의 시 알려 주도록 안내한다 |

연결 단계(HTTP) 오류는 도구가 아예 보이지 않거나 연결 실패로 나타난다.

| 증상 | 안내 |
|---|---|
| 401 (로그인 필요·연결 해제·만료) | `/mcp` 에서 앱박스 서버를 골라 다시 로그인(Authenticate)하도록 안내한다. 콘솔 계정 > MCP 연결에서 연결을 해제했거나, 비밀번호를 바꿨거나, 30일 동안 쓰지 않아 자동 해제됐으면 다시 연결해야 한다 |
| 403 `insufficient_scope` | 연결 권한이 부족하다. 다시 연결하고 허용 화면에서 필요한 권한(`apps:read`·`devices:read`)을 허용하도록 안내한다 |
| 403 (그 밖) | 계정 정지·베타 대상 아님 등 권한 추가로 풀리지 않는 거부다. 앱박스 고객지원에 문의하도록 안내한다 |
| 404 | MCP 기능이 꺼져 있거나 주소가 틀렸다. 플러그인 없이 수동으로 연결했다면 주소가 `https://console.appboxapp.com/api/mcp` 인지 확인하도록 안내한다 |
| 429 | 연결 요청이 너무 많다. 잠시 뒤 다시 시도한다 |

## 하지 말 것

- 비밀번호·API 키·FCM 자격증명 값을 묻거나 대화에 적게 하지 않는다. 로그인은 브라우저의 앱박스 화면에서만, 자격증명은 앱박스 콘솔 화면에서만 다룬다.
- 도구 응답에 없는 기기 수·원인을 지어내지 않는다.
- 같은 도구를 오류 뒤에 여러 번 반복 호출하지 않는다(재시도는 최대 1회).

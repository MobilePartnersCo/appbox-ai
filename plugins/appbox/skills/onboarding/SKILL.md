# 앱박스 시작 안내

고객이 푸시를 보낼 수 있을 때까지 **지금 상태 → 다음 한 단계**를 안내한다.
이 스킬은 **조회만** 한다 — 예외는 앱 등록 하나다(아래 2단계, 연결할 때 「앱 등록」 권한을 켠 경우만). 키 등록·빌드·발송은 고객이 앱박스 콘솔에서 직접 한다.

사용자가 넘긴 인자: `$ARGUMENTS` (비어 있을 수 있음)

## 원칙

- **한 번에 한 단계만** 안내한다. 고객이 끝냈다고 하면 도구를 다시 호출해 확인한 뒤 다음으로 넘어간다.
- 도구가 돌려준 `note`·`consoleUrl`·`guideUrls` 를 그대로 쓴다. 주소를 지어내거나 고쳐 쓰지 않는다.
- `consoleUrl` 이 `null` 이면 주소 대신 콘솔 메뉴 이름으로 안내한다.
- 단계의 자세한 방법을 물으면 `guideUrls` 를 안내하고, 서버가 문서 도구를 제공하면 `appbox_search_docs` → `appbox_get_doc` 으로 가이드 본문을 읽어 설명한다(없으면 주소만 안내).
- 비밀번호·키 파일 내용·인증키를 묻지 않는다. 고객이 붙여 넣으려 하면 말리고 콘솔 화면에서 직접 올리게 한다.

## 절차

### 1. 상태 확인 — `appbox_get_onboarding_status`

인자가 앱 코드 형식(영숫자·하이픈 10자 이하, 예 `ABC-123456`)이면 `{ "app": "<앱 코드>" }`, 아니면 `{}` 로 호출한다.

응답의 `stage` 로 갈린다.

| `stage` | 뜻 | 할 일 |
|---|---|---|
| `NO_APP` | 이 연결에서 볼 수 있는 내 앱이 없다(앱이 아직 없거나, 연결한 뒤에 만들어 이 연결에 허용되지 않았다) | 2단계(앱 만들기) |
| `CHOOSE_APP` | 내 앱이 여러 개다 | `apps` 를 이름·앱 코드로 보여 주고 어느 앱인지 묻는다. 인자로 앱 이름을 받았으면 `apps` 에서 이름이 일치하는 앱을 고른다. 고른 앱 코드로 다시 호출한다 |
| `SETUP` | 앱은 있고 준비가 덜 됐다 | 3단계(다음 단계 안내) |
| `READY` | FCM 등록과 기기 활동이 확인됐다 | 4단계(준비 완료) |

`connectionLimited` 가 `true` 면 "이 연결은 연결할 때 고른 앱만 볼 수 있고, 그 뒤에 만든 앱은 다시 연결해야 보인다"고 한 줄 덧붙인다.

### 2. 앱이 없을 때 (`NO_APP`)

먼저 고객의 상황을 한 번 묻는다. 답에 따라 안내가 달라진다.

| 고객 상황 | 방식 | 순서 |
|---|---|---|
| 웹사이트만 있다 | 앱박스 빌드(웹사이트를 앱으로) | 앱 등록 → FCM 등록 → 콘솔에서 빌드 |
| 이미 앱이 있다 | 자체 앱에 SDK 연동 | 앱 등록 → FCM 등록 → SDK 연동 |
| 아무것도 없다 | 웹사이트부터 준비 | 앱박스 홈페이지의 빌드 체험으로 먼저 살펴보도록 안내 |

그다음 `steps` 의 `CREATE_APP` 항목대로 안내한다: 콘솔 첫 화면(`consoleUrl`)의 「앱 등록」에서 **앱 이름만** 넣으면 만들어진다.

**`appbox_create_app` 도구가 있으면**(연결할 때 「앱 등록」 권한을 켠 경우) 대신 만들어 줄 수 있다. 이때는 다음을 지킨다.

- 고객이 앱을 만들겠다고 **분명히 말했을 때만** 부른다. 이름(1~20자)은 고객에게 확인받은 값을 쓴다.
- 결과의 `addedToConnection` 이 `true` 면 이 연결에서 바로 쓸 수 있다 — 다시 연결할 필요 없이 1단계로 돌아가 `{ "app": "<새 앱 코드>" }` 로 다시 확인한다.
- `false` 면 아래처럼 다시 연결해 새 앱을 허용하도록 안내한다.
- 도구가 없으면 콘솔에서 만들도록 안내한다(권한을 켜려면 다시 연결하면서 「앱 등록」을 켠다).

등록을 마쳤다고 하면 **앱박스에 다시 연결해 새 앱을 허용**하도록 안내한다. 연결한 뒤에 만든 앱은 기존 연결에 자동으로 들어가지 않는다.

- 쓰고 있는 AI 앱의 MCP 설정에서 `appbox` 연결에 다시 로그인하고, 동의 화면의 「허용할 앱」에서 새 앱을 체크한다.
- 같은 AI 앱에서 다시 연결하면 대부분 기존 연결이 새 범위로 바뀐다. 콘솔 계정 관리에 같은 이름의 연결이 하나 더 생겼다면 오래된 쪽을 해제한다.

다시 연결했다고 하면 1단계로 돌아가 다시 확인한다.

### 3. 다음 단계 안내 (`SETUP`)

`nextStep` 이 가리키는 `steps` 항목 **하나만** 자세히 안내하고, 나머지는 한 줄 목록으로만 보여 준다.

| `nextStep` | 안내 |
|---|---|
| `FCM` | FCM 등록이 먼저다(빌드 화면이 FCM 값으로 패키지명을 채우고, 푸시와 앱 내 SNS 로그인이 FCM 을 필요로 한다). **`setup-fcm` 스킬로 넘겨 단계별로 안내한다** |
| `BUILD_OR_SDK` | 웹사이트만 있으면 콘솔 빌드 화면(`consoleUrl`)에서 앱 이름·도메인으로 빌드, 이미 앱이 있으면 SDK 연동. 어느 쪽인지 모르면 묻는다. `note` 가 빌드 진행 중이라고 하면 끝날 때까지 기다리게 하고 `appbox_get_build_status` 로 확인한다 |
| `DEVICES` | 상태가 `TODO` 면 빌드한 앱을 기기에 설치·실행(또는 SDK 를 넣은 앱 실행)하고 알림 권한을 허용하게 한다. `WARN` 이면 최근 30일 활동이 없는 것이므로 `check-setup` 스킬로 넘겨 원인을 점검한다 |

- `API_KEY` 가 `OPTIONAL` 이면 "고객사 서버에서 직접 발송할 때만 필요"라고만 알리고 넘어간다. 고객이 서버 연동을 원한다고 하면 그 항목의 `consoleUrl` 을 안내한다.
- 고객이 단계를 끝냈다고 하면 **반드시 도구를 다시 호출해** 상태가 바뀌었는지 확인한다. 바뀌지 않았으면 무엇이 빠졌는지 `note` 로 설명한다.

### 4. 준비 완료 (`READY`)

"푸시를 보낼 준비가 됐다"고 알리고 다음을 안내한다.

1. 콘솔 › 메시지 발송 › 푸시 메시지에서 테스트로 한 번 보내 본다(발송은 콘솔에서 직접).
2. 서버에서 자동 발송하려면 `API_KEY` 항목의 화면에서 서버 IP 등록과 인증키 생성을 한다.

## 결과 정리 형식 (한국어)

```
## <앱 이름> (<앱 코드>) 시작 단계

- [x] 앱 등록
- [ ] FCM 등록  ← 지금 할 일
- [ ] 빌드 또는 SDK 연동
- [ ] 기기 등록 확인
- ( ) 서버 API 키 — 서버에서 발송할 때만

### 지금 할 일
(nextStep 항목의 안내 — 화면 주소, 가이드 주소 포함)
```

`DONE` 은 `[x]`, `TODO` 는 `[ ]`, `WARN` 은 `[!]`, `OPTIONAL` 은 `( )` 로 표시한다.

## 오류 처리

도구 오류는 `isError: true` 와 함께 `{"error":{"code","message","hint"}}` 로 온다. `message`·`hint` 를 그대로 전달한다.

| 코드 | 안내 |
|---|---|
| `APP_NOT_FOUND` | 앱 코드가 틀렸거나 이 연결로 볼 수 없는 앱이다. `app` 없이 다시 호출해 목록을 보여 준다 |
| `TOOL_DISABLED` | 앱박스가 이 도구를 일시적으로 막아 두었다. 콘솔에서 직접 확인하도록 안내한다 |
| `RATE_LIMITED` · `BUSY` | `retryAfterSec` 초 뒤 한 번만 다시 시도한다 |
| 도구가 목록에 없음 | 서버가 아직 이 도구를 제공하지 않는다. `appbox_list_apps` → `appbox_check_app_setup` 으로 같은 판단을 한다(앱 0개=앱 없음, FCM `MISSING`=FCM 등록, 기기 `MISSING`=기기 등록) |
| 그 밖 | `check-setup` 스킬의 오류 표를 따른다 |

## 하지 말 것

- 키 파일·비밀번호·인증키를 대화로 받지 않는다.
- 여러 단계를 한꺼번에 쏟아 내지 않는다.
- 도구가 주지 않은 주소·메뉴 이름을 지어내지 않는다.
- 발송·빌드·설정 변경을 대신 했다고 말하지 않는다(이 연결은 조회만 한다).
